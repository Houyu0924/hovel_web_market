# HOVEL 利益1,000万円までのロードマップ v1

Date: 2026-08-09
Status: Active hypothesis / 未検証
Owner: HOVEL

## 目的
HOVELのCustomer Understanding事業で、年間事業利益1,000万円を超えるまでのプロセスを、案件数・単価・粗利・商品進化・営業条件に分解する。

重要: これは現時点の仮説モデルであり、価格受容性・受注率・工数・継続率は未検証。最初の有料案件で更新する。

---

## 結論
3万円/5万円のSprintを大量販売するだけでは、利益1,000万円には届きにくい。

HOVELは以下の順に進化する。

**低価格Pilot → 高単価Sprint → Problem別専門商品 → 継続支援 → 顧客知識資産 / AI支援による高粗利化**

利益1,000万円時点の目安は、年間売上1,800万円前後、粗利率75%前後、年間固定費300万円以下。

例:
- 年商: 1,800万円
- 直接原価: 450万円（25%）
- 粗利: 1,350万円
- 固定費: 300万円
- 事業利益: 1,050万円

したがって、最終目標は「案件数最大化」ではなく、**1社あたり売上・継続率・粗利率の向上**。

# Phase 1 — 最初の3件: 市場が払うProblemを特定

## 価格
- Pilot: 3万円
- 通常テスト: 5万円

## 目標
有料3件。

## 学ぶこと
- 誰が買うか
- どのTriggerで反応するか
- Message / Pricing / ICP / Differentiation / Evidence / Win-Loss のどれに最も予算が付くか
- 1案件の実工数
- 顧客アクセスが可能か
- Decision Memoが実際に意思決定を変えるか

## 判断ルール
3案件のうち同じProblemが2〜3件重なったら、そのProblemを次の主力候補にする。

まだ商品を増やさない。

## 売上イメージ
3万円 × 3件 = 9万円

利益額ではなく、**何にお金が払われたか**がKPI。

---

# Phase 2 — 4〜10件目: 価格を上げ、実績を作る

## 価格仮説
- Entry diagnosis: 5〜8万円
- Core Sprint: 10〜15万円

価格は実績・工数・顧客価値を見て段階的に検証する。

## 商品
Customer Understanding Sprintは維持するが、営業入口ではProblem別名称を使う。

例:
- Message Diagnosis
- Pricing Diagnosis
- ICP Diagnosis
- Win/Loss Diagnosis

## 必須成果
- Before / After事例 3件
- 顧客コメント
- 「何を変えたか」が分かる事例
- できればCVR、商談化率、受注率、価格受容などの数値変化

## 売上イメージ
平均10万円 × 7件 = 70万円追加

累計売上100万円前後が目安。

# Phase 3 — 勝ち筋集中: 15〜30万円の商品へ

## 移行条件
以下のうち3つ以上を満たす。
- 5件以上の有料案件
- 同じProblemが3件以上
- 顧客が成果物を実際の意思決定に使用
- 2社以上から紹介 / 再依頼
- 1案件の標準工数が把握できている

## 価格仮説
15〜30万円 / Sprint

## 価値の売り方
「5人に聞きます」ではなく、

**『価格を変えるべきか、訴求を変えるべきか、誰を狙うべきかを決めます』**

を売る。

## 目標粗利率
70%以上。

AIで以下を圧縮:
- desk research
- transcript整理
- clustering
- competitor summary
- report draft

人間は:
- 誰に聞くか
- 何を深掘るか
- どう解釈するか
- 何を変えるか

に集中する。

# Phase 4 — 単発から継続へ: 月額20〜30万円

単発Sprintだけでは毎月営業が必要になる。

利益1,000万円を狙うには、一部を継続収益へ移す。

## 継続商品の仮説
### Customer Decision Partner
月額20〜30万円

内容例:
- 月次Customer Interview
- Lost deal review
- Message / Pricing定点観測
- 競合変化確認
- 月次Decision Memo
- 次の検証設計

「調査代行」ではなく、**毎月顧客情報から経営判断を更新する機能**として売る。

## 目標
継続顧客3〜4社。

例:
- 月25万円 × 4社 = 月100万円
- 年間1,200万円

ここに単発Sprintを加える。

---

# Phase 5 — 利益1,000万円ライン

## 推奨モデル例

### 継続収益
4社 × 月25万円 × 12ヶ月 = 1,200万円

### 単発Sprint
月1件 × 30万円 × 12ヶ月 = 360万円

### 高単価プロジェクト / Win-Loss等
年2件 × 120万円 = 240万円

### 年商
合計: 1,800万円

### コスト仮説
直接原価25% = 450万円
固定費 = 300万円

### 事業利益
1,800 - 450 - 300 = **1,050万円**

このモデルなら、月間案件数を大量に抱えず利益1,000万円を狙える。

# 価格進化ルール

値上げはカレンダーではなく証拠で行う。

## 3万円 → 5万円
最初のPilotで支払いが成立。

## 5万円 → 10万円
3件有料 + 納品再現性確認。

## 10万円 → 15〜30万円
意思決定変更の実績 / 顧客成果 / 紹介が発生。

## 30万円以上
顧客にとっての経済価値が数十〜数百万円以上と説明できる。

## 月額化
同じ会社で3ヶ月以内に複数回のCustomer Understanding需要が発生。

# 失敗条件

以下ならモデルを修正する。

### 1. 30社へ高品質接触してProblem Interviewがほぼ取れない
→ Target / Trigger / Entry Problemが間違っている。

### 2. Interviewは取れるが有料化しない
→ Problemはあるが支払い優先度が低い、またはOfferが弱い。

### 3. 受注するが工数が大きすぎる
→ 対象人数・調査範囲・納品を削る。AI化・テンプレ化。

### 4. 単発で終わる
→ 継続需要がない可能性。別Problemを探す。

### 5. 価格を上げると全く売れない
→ 経済価値が弱いか、買い手が違う。

# HOVELがやらないこと

利益1,000万円まで、以下は原則やらない。
- 大規模SaaS開発
- 大量採用
- 多業種への無差別営業
- 商品を6種類すべて独立販売
- 広告費を大量投入
- 売上がない段階で法人固定費を増やす

まずサービスでProblemと支払い意思を学び、再現性が出た箇所だけ資産化する。
