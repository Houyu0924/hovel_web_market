# Customer Understanding事業の海外変遷トレース v1

Date: 2026-08-09
Status: Active
Owner: HOVEL

## 目的

HOVELのCustomer Understanding事業を、海外で先行したユーザー調査・顧客理解・Win/Loss・Customer Intelligence市場の変遷に沿って設計する。

重要なのは「今の海外企業をそのまま真似る」ことではない。

**市場がどの順番で価値を増やし、どこで課金ポイントが生まれたかをトレースし、HOVELはその進化を圧縮して追う。**

---

## 海外市場の変遷

### Stage 0: 伝統的な市場調査

主な形:
- アンケート
- フォーカスグループ
- 調査会社への委託
- 長いレポート

価値:
- 顧客を知る

弱点:
- 遅い
- 高い
- 実務の意思決定から遠い
- 調査を実施すること自体が目的化しやすい

HOVELへの示唆:
- 「調査レポート」を売らない
- 調査量を価値にしない

---

### Stage 1: 2007〜 — UserTesting型「高速アクセス」

UserTestingは2007年から、人がWebサイトやプロダクトを使う様子を短時間で取得できるモデルを拡大した。

市場の進化:

**調査会社に頼んで数週間待つ → 実際のユーザーから数時間でフィードバックを得る**

課金ポイント:
- 対象ユーザーへのアクセス
- スピード
- 動画・発話という一次情報

その後、UXだけでなくProduct、Marketing、CXへ対象を拡張。

HOVELへの示唆:
- 一次情報取得は価値だが、それだけでは成熟するとコモディティ化する
- 速度は必須条件であり、最終差別化にはならない

---

### Stage 2: 2015〜 — User Interviews / Chattermill型「調査工程のボトルネック解消」

#### User Interviews

2015年以降、ユーザー調査で大きな手間だった「誰に聞くか・対象者をどう集めるか」を独立した商品にした。

進化:

**調査ツール → 調査対象者へのアクセス自体を商品化**

#### Chattermill

2015年創業。大量の自由回答や顧客フィードバックを人手で読む問題を、機械学習で自動化する方向へ進化した。

進化:

**顧客の声を集める → 顧客の声を大量に処理する**

HOVELへの示唆:
- 「誰に聞くか」は重要な価値
- AIが代替しやすいのは整理・分類・要約部分
- 人間の価値は対象者設計、深掘り、意味づけに残る

---

### Stage 3: 2017〜 — Clozd型「経営課題別のPoint Solution」

Clozdは2017年、「なぜ案件に勝った／負けたのか」を直接買い手に聞くWin/Lossに特化した。

大きな変化:

**Customer Researchという広い予算ではなく、Sales Win Rateという経営KPIに接続した。**

課金理由:
- 営業担当者の推測ではなく、買い手本人から理由を取る
- 価格、競合、営業、製品、メッセージを分離する
- 得られた情報をSales / Marketing / Productへ戻す

HOVELへの示唆:
- 「顧客理解」という抽象語だけでは弱い
- 最終的には特定KPI・意思決定に接続する必要がある
- HOVEL初期は広く受けてよいが、同じProblemが3件以上出たらPoint Solution化する

候補:
- Win/Loss Sprint
- Message Sprint
- Pricing / Packaging Sprint
- Customer Proof Sprint

---

### Stage 4: 2017〜2021 — Dovetail / Wynter型「Researchから意思決定へ」

#### Dovetail

初期のResearch Repositoryから、研究結果・インタビュー・サポート・営業・NPSなどを横断して扱うCustomer Intelligenceへ拡張。

進化:

**単発調査 → 組織に蓄積する顧客知識**

#### Wynter

2019年に創業者が「B2Bメッセージのどこが悪いか、Analyticsでは分からない」というProblemを認識し、2021年にB2B Message TestingのPoint Solutionとして開始。その後ICP Researchへ拡張。

進化:

**何でも調査する → B2B Messagingという具体的な意思決定に集中 → 周辺のICP Researchへ拡張**

HOVELへの示唆:
- 最初は狭いProblemで勝ち、その後周辺へ拡張する方が強い
- 「レポート」ではなく、次に変える内容まで提供する
- 顧客理解データを案件ごとに捨てず、再利用可能な知識へ変える

---

### Stage 5: 2023〜2026 — AI Customer Intelligence型

UserTestingは2023年にAI機能を本格展開し、DovetailもResearch RepositoryからAI-native Customer Intelligenceへポジショニングを広げている。

2026年にはUserTestingがUser Interviewsを買収し、
- participant access
- research execution
- AI analysis
- organizational workflow
を一体化する方向へ進んでいる。

市場の変化:

**一次情報取得 → 分析 → 保存 → 全社利用 → 意思決定支援**

さらにAIによって、収集・文字起こし・分類・要約は急激に安くなる。

結果として価値が残る場所:

1. 誰から情報を取るか
2. 何を聞くか
3. 何が本当に購買に影響しているか
4. 何を変えるべきか
5. 変えた結果どうなったか

HOVELが狙うべき場所と一致する。

---

## 海外市場の進化を1行で表す

**Research → Fast Feedback → Participant Access → Point Solution → Customer Intelligence → AI-assisted Decision System**

日本語にすると:

**調査する → 早く聞く → 正しい人に聞く → 特定の経営課題を解く → 顧客情報を蓄積する → AIで継続的に意思決定する**

# HOVELが圧縮して辿るべき進化

海外企業は10〜20年かけて進化しているが、HOVELは既存技術を使えるため、全工程を自社開発する必要はない。

## HOVEL Phase 0 — 2026年8月

### 準備

商品:
Customer Understanding Sprint

価値:
**営業を増やす前に、なぜ売れないかを顧客から特定し、次に変える3つを決める。**

やること:
- ICP仮説
- Problem Interview
- 5〜8名の一次情報
- 軽い定量
- Sales / Lost data
- 競合情報
- Decision Memo

AI:
- 調査候補
- 質問案
- 文字起こし
- クラスタリング
- レポート下書き

人間:
- 誰に聞くか
- 深掘り
- 解釈
- 優先順位
- 最終Decision

## HOVEL Phase 1 — 最初の有料3案件

目的:
**どのProblemに本当にお金が払われるかを特定する。**

絶対にやらない:
- SaaS開発
- 独自パネル構築
- 大規模自動化
- 商品を5種類に分ける

計測:
- 何を理由に発注したか
- 最も価値があった納品部分
- 実際に変更した項目
- 変更後のKPI
- HOVEL作業時間

分岐条件:
同じProblemが3案件以上出たら商品化候補。

例:
- Messagingが3件 → Message Sprint
- 失注理由が3件 → Win/Loss Sprint
- 稟議証拠不足が3件 → Customer Proof Sprint

---

## HOVEL Phase 2 — 3〜10有料案件

目的:
**Point Solutionを発見する。**

海外のWynter / Clozdに相当する段階。

Customer Understanding Sprintを入口として残しつつ、売れたProblemを1つ強くする。

理想状態:

「顧客理解をやります」ではなく、

例:
**商談はあるのに受注率が低いB2B企業向けのWin/Loss Sprint**

まで具体化。

価格:
- Pilot 3万円
- 初期通常 5万円
- Problemの経済価値が確認できたら単価を上げる

---

## HOVEL Phase 3 — 10〜30案件

目的:
**単発サービスからCustomer Intelligence Assetへ進化。**

やること:
- 共通質問DB
- 業種別障壁DB
- 価格反応DB
- 競合比較軸
- Decisionパターン
- Before / Afterデータ

顧客別にも過去の一次情報を蓄積する。

ここで初めて継続サービスを検討:
- 四半期Win/Loss
- 定期Message Test
- Quarterly Customer Intelligence Review

---

## HOVEL Phase 4 — 30案件以降 / 明確な反復Problem発見後

目的:
**AI / Software layerを追加する。**

条件:
- 同じ作業を毎案件している
- 顧客が継続的に同じ分析を欲しがる
- 手作業が粗利を圧迫する
- データの蓄積自体に価値が出ている

ここで初めて検討:
- Interview synthesis agent
- Win/Loss database
- 顧客シグナルmonitor
- Decision recommendation UI
- 顧客向けCustomer Intelligence workspace

重要:

**Softwareを先に作らない。Serviceで反復Problemを発見してからSoftware化する。**

# 海外変遷から見たHOVELの長期ポジション

HOVELが最終的に目指すべきなのは「調査会社」ではない。

また「AI分析ツール」だけでもない。

最終像:

> **B2B企業のCustomer Intelligence Layer**
>
> 顧客・見込み顧客・失注・営業・競合からCustomer Signalを集め、経営判断へ変換する。

ただし、これは現在の商品名にはしない。

現在売るものは具体的なSprint。

# 今の戦略判断

## 継続する

- Customer Understanding Sprint
- 5〜8名の一次情報
- Decisionを最大3つに限定
- 新サービス / 新料金 / 法人展開Triggerの企業を狙う
- 海外Point Solution市場をベンチマーク

## 追加する

案件ごとに「海外進化マップ上のどのProblemだったか」を記録する。

分類:
- Message
- Positioning
- Win/Loss
- Pricing
- Competitive
- Customer Proof
- Research Access
- Customer Intelligence

これにより3案件目以降の商品分化をデータで決める。

## やらない

- 最初からDovetailを作る
- 最初からUserTestingを作る
- モニター登録者を大量保有する
- AI SaaSを先に開発する
- 「何でもマーケティング調査」に広げる

# HOVELの重要原則

海外市場の歴史から見ると、価値は一貫して上流から下流へ移っている。

昔:
**情報を集められること**

次:
**正しい人から早く集められること**

次:
**特定の問題に答えられること**

現在:
**大量のCustomer Signalから正しい意思決定を出せること**

したがってHOVELのコアは今後も:

**Customer Signal → Decision → Validation**

とする。
