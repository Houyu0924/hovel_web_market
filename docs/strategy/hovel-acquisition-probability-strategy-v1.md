# HOVEL 受注確率最大化戦略 v1

Date: 2026-08-09
Status: Active
Owner: HOVEL

## 目的

2026年9月からCustomer Understanding Sprintの初回有料案件を獲得するために、営業量ではなく**受注確率を最大化する**。

HOVELは「顧客理解サービス」を売らない。

**Triggerが発生したB2B企業に対して、いま判断に困っている1つのProblemを特定し、その判断を一次情報で解く。**

---

## 海外ベンチマークから学ぶこと

### Wynter
- B2BメッセージがICPに刺さっているか、という具体的Problemに一点集中
- Clarity / Relevance / Value / Differentiationを顧客本人から検証
- Appcues事例ではメッセージ改善後、visit-to-trial conversionが73%改善

### FletchPMM
- 「positioningが曖昧」というProblemを短期Sprintで解く
- B2B softwareに絞り、Before / Afterを大量に蓄積
- Sierra Interactiveではupmarket移行というTriggerに対し、対象顧客・差別化・競合比較を明確化

### Clozd
- CRMや営業担当者の失注理由ではなく、実際のbuyerに直接聞く
- Win/Lossをproduct / pricing / messaging / competition / sales executionの意思決定へ接続
- 調査ではなく、win rate改善に繋がるDecision Intelligenceとして売る

## HOVELへの翻訳

海外の共通構造:

1. 特定の経営Problemに絞る
2. 正しいbuyer本人に聞く
3. 結果を意思決定へ落とす
4. Before / AfterをProof化する
5. 同じProblemが増えてから商品を細分化する

HOVELもこの順序を守る。

# 受注確率の6レバー

## 1. WHO — 誰に売るか

業種よりTriggerを優先する。

即アプローチ条件:
- 直近90日以内に新サービス開始
- 法人プラン開始
- 新料金 / 料金改定
- β / 先行導入開始
- Upmarket / 新ICP展開
- LP / positioning刷新
- 商談はあるが失注理由が曖昧

原則、12点Target Scorecardで10点以上の企業だけをWIPへ入れる。

### 初期優先市場
- B2B SaaS / 法人向けSoftware
- 法人研修 / B2B Education
- 新規AI / DX B2B service
- B2B consulting /業務支援

---

## 2. WHY NOW — なぜ今連絡するか

初回接触には必ず直近Triggerを1つ入れる。

NG:
> 顧客理解のお手伝いができます。

OK:
> 新料金体系への変更を拝見しました。現在の商談で「価格が障壁なのか、価値理解が障壁なのか」を切り分ける必要が出やすいタイミングではないかと考え、ご連絡しました。

HOVEL側の仮説は必ず「仮説」と表現する。

---

## 3. WHAT — 何を売るか

Customer Understandingを売らず、**Decision**を売る。

初期Problem分類:

### P1 Message
誰に何を伝えれば刺さるか不明

### P2 Pricing
価格が本当に障壁なのか不明

### P3 ICP
どの顧客層を優先すべきか不明

### P4 Differentiation
競合 / 代替との差が伝わらない

### P5 Evidence
稟議・購入を後押しするProofが足りない

### P6 Win/Loss
商談はあるが、なぜ勝つ / 負けるか不明

1社に対して初回は1Problemだけ持っていく。

---

## 4. ENTRY — 最初の15分

初回は売らない。

目的:
**Problemが実在し、相手がそのProblemを重要と認識しているか確認する。**

質問例:
1. 最近、想定より反応が良い顧客層はありますか？
2. 商談で説明し直すことが多い箇所はどこですか？
3. 最も多い導入保留理由は何ですか？
4. 価格に対する反応はどの段階で出ますか？
5. 今、顧客について分からず判断に困っていることは何ですか？

### Paid Pilot提示条件
次の3条件を満たした場合のみ提示する。

- Problemが具体的
- 意思決定期限がある
- 顧客本人に聞けば判断が改善する

Problemが弱い場合は売らない。

---

## 5. OFFER — 3万円Pilotの売り方

売るもの:

**7〜10日で、何を変えるべきかを決める。**

例:
> 5名程度の対象顧客から一次情報を取り、価格を下げるべきなのか、訴求を変えるべきなのか、ターゲットを絞るべきなのかを整理します。最後に次に変える3つだけをDecision Memoとしてお返しします。

### Pilot
- Price: ¥30,000
- Duration: 7〜10日
- Theme: 1 Problem
- Qualitative: 5名目安
- Deliverable: Decision Memo + customer evidence summary
- Recommendation: max 3

### 通常テスト
- ¥50,000

### 3万円の意味
安売りではなく、HOVEL側もProduct-Market Fitを検証しているInitial Pilot価格。

---

## 6. PROOF — なぜHOVELを信じるか

初期はHOVEL自身のB2B実績が少ない。

したがってProofは3層で作る。

### Layer 1: Process Proof
- freee Lab #001
- 顧客理解 → Insight → Decision → Validationの公開実験

### Layer 2: Overseas Market Proof
- Wynter
- FletchPMM
- Clozd
など、同Problemに海外で予算が付いていることを示す。

※海外企業の成果をHOVEL自身の成果として表現しない。

### Layer 3: Client Proof
最初のPilot案件から
- Before
- Problem
- Evidence
- Decision
- Implemented change
- Measured result
を蓄積する。

3件揃ったら営業資料 / LPへ反映。

# 受注率改善ルール

## 返信がない
文章より先に以下を疑う。
1. Triggerが弱い
2. 担当者が違う
3. Problem仮説が弱い

## InterviewにはなるがProblemがない
Target ScorecardのCustomer Understanding Gapの採点が甘い。

## ProblemはあるがPilotを買わない
以下を記録する。
- 緊急度
- 予算
- 自社でできる認識
- 顧客アクセス可否
- 信頼不足
- 成果物が弱い

## Pilotは売れるが利益が出ない
Delivery SOP / AI automation / respondent sourcingを改善する。
