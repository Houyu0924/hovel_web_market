# HOVEL Business Model Lock v1.0

Date: 2026-08-08

## Mission

HOVELは、**市場に存在する強いProblemを発見し、AI＋人間で驚くほど良い解決策に変え、本当に必要とする少数顧客へ高粗利で販売する。**

大量PV・大量顧客・低価格競争は主戦場にしない。

## North Star

**有料で成立したHOVEL Solution数**

当面の目標は 1 Solution。

## Core Loop

1. Market Problem Intake
   - 業務委託市場
   - 企業の募集・求人・外注案件
   - AI発信者・企業のAI活用主張
   - 公開ユースケース
   - 顧客ヒアリング

2. HOI Scoring
   - Problem severity
   - 実際の支払市場
   - 単価余地
   - 発生頻度
   - AI処理率
   - 人間判断価値
   - 標準化可能性
   - 継続課金可能性
   - 法務・規制リスク
   - データ入手難易度
   - 実質時給ポテンシャル

3. HOVEL Experiment
   - 実在タスクをAI＋人間で完遂
   - AI担当工程 / 人間担当工程を明示
   - 時間・原価・品質・修正量を記録

4. Publish
   - 「AIでできる？」を実験記事化
   - 成功だけでなく失敗条件も公開
   - 記事は集客だけでなく実績・営業資料・研究ログとして使う

5. Sell
   - 最初は1顧客
   - 次に3顧客
   - 次に10顧客
   - 同じProblemで再現しない限り拡大しない

6. Productize
   - SOP化
   - テンプレート化
   - 定額化
   - 継続監視 / 継続分析
   - 必要に応じてソフトウェア化

## Positioning

HOVELはAI教育メディアでも、AIツール紹介メディアでも、格安受託会社でもない。

**市場で実際にお金が払われている面倒を、AIが処理し、人間が判断する形へ再設計する会社。**

## First Product Hypothesis

### HOVEL Market Intelligence Sprint

顧客の代わりに市場・競合情報を収集、整理、検証し、経営判断に必要な変化だけを届ける。

AI:
- 情報収集
- 分類
- 比較表作成
- 要約
- 初期仮説

Human:
- 調査設計
- 情報源評価
- 競合選定
- 矛盾確認
- 意味付け
- 最終提案

将来形:
**単発レポート → 月次競合監視 → 経営判断インテリジェンス**

## Revenue Principle

年間利益1,000万円を大量顧客で狙わない。

例:
- 20社 × 年間利益50万円 = 1,000万円
- 10社 × 年間利益100万円 = 1,000万円

少数顧客あたりの価値と粗利を上げる。

## Hourly Economics

- 実質時給5,000円未満: 原則Stop
- 10,000円以上: 初期合格
- 20,000円以上: Scale候補

実質時給 = (売上 - 直接原価) / 人間実働時間

## Stop Doing

- PV目的の記事量産
- 低単価アフィリエイトの深追い
- 一般的なAIニュース転載
- 「何でもAI化できます」という広すぎる営業
- 価格競争型受託
- ツール名を商品価値にする
- 調査だけ続けて販売しない
- 1つ売れる前に新事業を追加する

## Strategic Lock

**最初のHOVEL Solutionが有料で3顧客に再現するまで、事業モデルを変更しない。**

戦術・対象Problem・価格・販売チャネルは変更可。

## Immediate Sprint

### HOI-0001

**Market Intelligence Sprint v0を実際に1本作る。**

Completion Criteria:
- 実在する1社を対象
- 競合10社
- 市場 / 商品 / 価格 / USP / SEO / SNS / レビュー / 顧客不満 / 市場空白を調査
- 経営判断につながる提案3点
- AI作業時間を記録
- 人間作業時間を記録
- AI担当率 / 人間担当率を記録
- 誤り・修正箇所を記録
- 想定販売価格を設定
- 実質時給を算出
- 最終成果物を第三者が読める形にする

### Gate

以下を満たせば販売テストへ進む。

- 納品可能品質
- 人間実働5時間以内を目標
- 実質時給10,000円以上の価格設計が可能
- 顧客が次の意思決定に使える具体的提案がある

満たせなければ商品を変える前に、工程と対象顧客を改善する。
