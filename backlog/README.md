# HOVEL Business Backlog

HOVELの経営タスクを、収益・集客・商品・コンテンツ・システム・調査の6カテゴリで一元管理する。

## 目的

- 毎週の優先順位をゼロから考えない
- AIエージェントごとの担当と完了条件を固定する
- 期待効果と工数を比較し、投資判断を記録する
- 完了・保留・撤退の履歴をGitHubに残す

## ディレクトリ

```text
backlog/
├── README.md
├── queue.csv
├── task-template.md
├── agents.md
└── weekly/
    └── 2026-W32.md
```

## カテゴリ

- Revenue: 売上・クリック・成約に直結
- Growth: PV・検索流入・X流入・フォロワー増加
- Product: 商品レビュー・比較・商品企画
- Content: 記事・動画・SNS素材
- System: GitHub・自動化・データ基盤
- Research: 市場調査・論文・競合分析

## 優先度

- P0: 事業停止や重大リスク。即時対応
- P1: 今週必須。KPIや収益に直結
- P2: 今月実行。重要だが緊急ではない
- P3: 候補。データが揃うまで保留可能

## ステータス

- Todo
- Doing
- Review
- Blocked
- Done
- Parked
- Dropped

## 週次運用

1. Data Agentが指標を更新する
2. Analyst Agentが課題と機会を抽出する
3. CEO Agentが`queue.csv`を再評価する
4. 今週のP1を最大3件に絞る
5. 完了条件を満たしたタスクだけDoneへ移す
6. 失敗・保留理由を必ず記録する

## 投資判断の原則

優先順位は、概ね次の順で決める。

1. 読者価値
2. 検証可能性
3. 収益への接続
4. 再利用性
5. 工数と費用
6. ブランド整合性

PVだけでなく、クリック、保存、返信、再購入意向、内部リンク価値を合わせて判断する。
