# HOVEL Loop Operating Procedure

## 0. 役割

- Owner: 最終承認、購入、公開、撤退判断
- AI Planner: 課題発見、優先順位、実験設計
- AI Executor: 下書き、集計、候補生成
- AI Verifier: 品質ゲート、証拠、停止条件の確認

同じAIを使う場合も、Planner / Executor / Verifierの出力を分離する。

## 1. 毎日

### Trigger

- 記事を公開した
- Xを投稿した
- 商品を使用した
- 数値を確認した

### Execution

- 該当CSVへ1行追加する
- 事実と仮説を分けて記録する
- 次の測定日時を設定する

### Verification

- 必須列が埋まっているか
- 体験していない内容が混ざっていないか
- 健康・商品効果の断定がないか

### Stop

品質ゲート不合格の場合、公開・推奨へ進めない。

## 2. 記事公開時

1. 読者課題を1つ定義
2. 取得したい指標を1つ定義
3. 記事品質ゲートを確認
4. 人間が公開を承認
5. X投稿3案を生成
6. 文体を変えて投稿
7. 24時間後と7日後に数値を記録
8. `continue / improve / stop` を暫定判定

## 3. X投稿ループ

### 投稿配分

- office_worker_observation: 40%
- hovel_lab_log: 30%
- evidence_plus_action: 30%

### 主要指標

1. プロフィール訪問
2. 返信
3. ブックマーク
4. リンククリック
5. インプレッション

フォロワー数だけで文体を判断しない。

### 30投稿後の収束条件

- 各文体が最低8本ある
- 文体別のプロフィール訪問率を比較できる
- 最も反応が良い文体を次月の基準へ昇格できる

## 4. 商品レビューループ

### オールドスパイス初期スケジュール

- Day 0: 商品・ラベル・購入価格・写真を記録
- Day 1: 初回使用
- Day 3: 平日の使用感
- Day 7: 1週間評価
- Day 30: 継続評価と最終判定

### 各回の必須記録

- 使用時刻
- 使用量
- 気温や通勤条件
- 香りの強さ
- 持続時間
- 肌・頭皮の反応
- 職場での使いやすさ
- 再購入意向

異常が出た場合は検証を停止する。

## 5. 毎週レビュー

### Trigger

毎週土曜日または日曜日に実行する。

### Execution

`prompts/weekly-review.md`を使用してレポートを作成する。

### Owner Decision

Ownerは次の3分類を承認する。

- Continue: 条件を維持して再実行
- Improve: 変数を1つ変更して再実行
- Stop: 中止し、理由を意思決定ログへ保存

### 翌週への入力

最重要実験は最大3件。4件以上は実行しない。

## 6. 初週タスク

- [ ] オールドスパイス2商品を登録
- [ ] Day 0の購入情報と写真を記録
- [ ] 初日使用データを記録
- [ ] X投稿14本を3文体に分類
- [ ] 価値ある返信35件
- [ ] 記事3本を公開または改善
- [ ] Amazonクリックを週次記録
- [ ] 週次レビューを作成
- [ ] 翌週の実験を3件以内に決定

## 7. 自動化の境界

v0.1では、GitHub Actionsによるデータ形式チェックと週次レポートの準備までを自動化対象とする。

自動公開、自動購入、健康判断、商品推奨の確定は対象外とする。
